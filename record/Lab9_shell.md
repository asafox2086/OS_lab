# xv6 Lab 9：简单 Shell 实验报告

## 一、改了哪里

### `user/nsh.c`

新增文件，实现函数：`runsegment()`、`runline()`、`main()`。

- `runsegment()`：在固定大小的局部参数数组中解析一段不含管道的命令；识别普通参数、`<` 和 `>`，完成文件描述符重定向后调用 `exec()`。
- `runline()`：查找最左侧 `|`，分别创建左右子进程，将左侧标准输出和右侧标准输入接到管道；右侧命令通过递归继续解析，因而支持多段管道。
- `main()`：初始化标准描述符，使用固定的全局命令行缓冲区读取输入，输出 `@ ` 提示符；每行命令由一个子进程执行，父进程等待该行完成。
- 每个新增或修改的函数体均以 `//my code begin` 和 `//my code end` 标记。实现只使用全局、局部固定数组和指针，没有使用 `malloc()`、`sbrk()` 或其他动态内存分配。

### `Makefile`

- 在 `UPROGS` 中加入 `$U/_nsh\`，使 `make fs.img` 将新 shell 编译并写入 xv6 文件系统镜像。

## 二、改之后的算法

Shell 读取一行命令后先删除结尾换行符。xv6 的 `gets()` 在 EOF 时会把缓冲区首字符设为 `0`，因此以 `line[0] == 0` 结束 shell，避免 EOF 后重复打印提示符。普通空行则在删除换行符后跳过。

执行单段命令时，`runsegment()` 原地把空白和重定向符替换为字符串结束符，参数数组直接指向命令行缓冲区，无需复制或分配内存。遇到 `< file` 时关闭描述符 `0` 并以只读方式打开文件；遇到 `> file` 时关闭描述符 `1` 并以创建、只写方式打开文件。随后调用 `exec(argv[0], argv)`；系统调用失败会向描述符 `2` 输出错误并退出。

执行管道时，`runline()` 将最左侧 `|` 分隔为左右命令，创建一个管道和两个子进程。左子进程把管道写端复制到标准输出，右子进程把管道读端复制到标准输入；右侧递归调用 `runline()`，所以 `a | b | c` 能继续拆分。父进程及两个子进程都会关闭不再需要的管道端，再等待子进程，保证读端能收到 EOF，且不泄漏文件描述符。实现检查 `open()`、`pipe()`、`fork()` 和 `dup()` 的返回值，错误信息始终写到标准错误，不影响 `testsh` 重定向的标准输出。

一行命令的完整流程是：`main()` 先把控制台补足为描述符 0、1、2，向标准错误输出 `@ `，再以固定数组读取一行。读取后删除换行；首字符为零表示 EOF 并退出，删除换行后为空则跳过。父 shell 为每一行 `fork()`，子进程调用 `runline()`；无管道时 `runsegment()` 原地将分隔符改为字符串结束符，参数数组直接引用该行缓冲区。遇到重定向时先关闭 0 或 1，再要求 `open()` 恰好返回该描述符；最后 `exec()` 替换子进程。父 shell 只等待该行最外层子进程，因此提示符不会与前一行残留子进程交错。
